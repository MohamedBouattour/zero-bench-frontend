# 🏛️ Architecture & Implementation Plan: Toast & Skeleton Components with HttpInterceptor Loading

- **Timestamp:** 16_09_2026-23_10
- **Project:** BenchZero (ESN ERP)
- **Objective:**
  1. Create a Toast notification system (models, signals store/service, atomic toast card, and toast container widget) conforming to Stitch design tokens.
  2. Implement an atomic, reusable Skeleton placeholder widget (`app-skeleton`) with multiple variants (`text`, `circle`, `rect`, `card`, `table-row`), shimmer animation, and dark mode support.
  3. Create a reactive `LoadingService` / `LoadingStore` tracking active HTTP requests via a functional `loadingInterceptor` in Angular `provideHttpClient(withInterceptors([loadingInterceptor]))`.
  4. Create a top progress bar widget (`app-loading-bar`) rendered in the layout shell.
  5. Integrate toast triggers and skeleton placeholders into the Design System showcase and relevant feature tables.
  6. Ensure 100% strict typing, SSR safety, Zoneless compliance, zero test failures, and zero build errors.

## ⚡ 2. Technical Specifications

### A. Toast Notification System
- **Models (`toast.model.ts`):**
  - `ToastType = 'success' | 'error' | 'warning' | 'info'`
  - `Toast`: `{ id: string; type: ToastType; title?: string; message: string; duration?: number; createdAt: number }`
- **Service (`toast.service.ts`):**
  - State: `toasts = signal<Toast[]>([])`
  - Helpers: `success()`, `error()`, `warning()`, `info()`, `dismiss(id)`, `clear()`.
  - Auto-dismiss: Default 4500ms timeout with SSR check (`isPlatformBrowser(inject(PLATFORM_ID))`).
- **Widgets (`toast/`):**
  - High fidelity matching Stitch tokens:
    - `success`: Emerald `#10B981` border & chip, `check_circle` icon.
    - `error`: Crisp Red `#EF4444` border & chip, `error` icon.
    - `warning`: Amber `#F59E0B` border & chip, `warning` icon.
    - `info`: Electric Blue `#0058BE` border & chip, `info` icon.
  - Micro-interactions: Slide-in animation, manual dismiss button, glassmorphism backdrop.

### B. Skeleton Placeholder Component (`skeleton.component.ts`)
- **Configurable Inputs:**
  - `variant`: `'text' | 'rect' | 'circle' | 'card' | 'table-row'` (default: `'text'`).
  - `width`: CSS width string (e.g. `'100%'`, `'140px'`).
  - `height`: CSS height string (e.g. `'1rem'`, `'48px'`).
  - `count`: Repeat counter for list or row rendering (default: `1`).
  - `animated`: boolean (default: `true`, uses CSS shimmer pulse).
- **Styling:**
  - `bg-slate-200/80 dark:bg-slate-800/80 animate-pulse`
  - High contrast on both light and dark backgrounds.

### C. Loading Management & HttpInterceptor
- **Service (`loading.service.ts`):**
  - `activeRequests = signal<number>(0)`
  - `isLoading = computed(() => this.activeRequests() > 0)`
  - Methods: `show()`, `hide()`, `reset()`.
- **Interceptor (`loading.interceptor.ts`):**
  - Uses `HttpInterceptorFn`.
  - Supports `NO_LOADING_TOKEN` to allow background/polling calls to opt-out.
  - Calls `loadingService.show()` on request trigger.
  - Uses RxJS `finalize(() => loadingService.hide())` to ensure decrement even on cancellation/error.
  - Optional global error toast for unexpected HTTP 5xx failures.
- **Top Loading Bar (`loading-bar.component.ts`):**
  - Fixed top line `h-1 bg-gradient-to-r from-secondary-blue via-indigo-500 to-secondary-blue` with indeterminate pulse animation when `loadingService.isLoading()` is active.
