# 🏛️ Architecture & Implementation Plan: DDD Feature-Level Model Externalization

- **Timestamp:** 16_09_2026-23_05
- **Project:** BenchZero (ESN ERP)
- **Objective:**
  1. Relocate and externalize all inline and centralized interface/type declarations into scalable DDD domain-specific model directories (`src/app/features/<domain>/models/`).
  2. Remove inline state interfaces (`*State`) from NgRx SignalStore files.
  3. Clean up `src/app/core/models/` to only host shared global application infrastructure models (Theme, Language, Navigation, Breadcrumbs), while re-exporting domain types to maintain backward compatibility.
  4. Ensure zero build errors, zero test failures, and 100% strict TypeScript typing.

---

## 1. Domain-Driven Design (DDD) Model Organization

```
src/app/
├── core/
│   └── models/
│       ├── theme.model.ts             # ThemeMode, ThemeConfig
│       ├── language.model.ts          # SupportedLanguage, LanguageOption, Translations
│       ├── navigation.model.ts        # NavItem, NavSection
│       ├── breadcrumb.model.ts        # BreadcrumbItem (extracted from breadcrumbs.component.ts)
│       └── index.ts                   # Core models barrel export
│
└── features/
    ├── bench-risk/
    │   └── models/
    │       └── bench-risk.model.ts    # RiskMetrics, RiskOverviewResponse, BenchRiskState
    │
    ├── consultants/
    │   └── models/
    │       └── consultant.model.ts    # ConsultantStatus, Consultant, ConsultantsState
    │
    ├── customers/
    │   └── models/
    │       └── customer.model.ts      # ClientAccount, ClientsState
    │
    ├── placements/
    │   └── models/
    │       └── placement.model.ts     # PlacementStage, PlacementOpportunity, PlacementsState
    │
    ├── skills-gap/
    │   └── models/
    │       └── skills-gap.model.ts    # SkillDemandLevel, SkillDemandMetric, SkillsGapState
    │
    └── pitch-generator/
        └── models/
            └── pitch-generator.model.ts # PitchTone, PitchRequest, PitchResponse, PitchGeneratorState
```

## 2. Refactoring Tasks & Impact

1. **`src/app/features/bench-risk/`**:
   - Create `models/bench-risk.model.ts` with `RiskMetrics`, `RiskOverviewResponse`, and `BenchRiskState`.
   - Update `stores/bench-risk.store.ts` to import `BenchRiskState` from `../models/bench-risk.model`.
   - Update `services/bench-risk-api.service.ts` to import from `../models/bench-risk.model`.

2. **`src/app/features/consultants/`**:
   - Create `models/consultant.model.ts` with `ConsultantStatus`, `Consultant`, and `ConsultantsState`.
   - Update `stores/consultants.store.ts` to import `ConsultantsState` from `../models/consultant.model`.
   - Update `services/consultants-api.service.ts` to import from `../models/consultant.model`.
   - Update `consultants.component.ts` imports.

3. **`src/app/features/customers/`**:
   - Create `models/customer.model.ts` with `ClientAccount` and `ClientsState`.
   - Update `stores/clients.store.ts` and `services/clients-api.service.ts`.
   - Update `customers.component.ts`.

4. **`src/app/features/placements/`**:
   - Create `models/placement.model.ts` with `PlacementStage`, `PlacementOpportunity`, and `PlacementsState`.
   - Update `stores/placements.store.ts` and `services/placements-api.service.ts`.
   - Update `placements.component.ts`.

5. **`src/app/core/components/breadcrumbs/`**:
   - Move `BreadcrumbItem` from `breadcrumbs.component.ts` to `src/app/core/models/breadcrumb.model.ts`.

6. **`src/app/core/models/`**:
   - Keep re-exporting domain models in `consultant.model.ts`, `risk.model.ts`, `customer.model.ts`, `placement.model.ts` so core widgets (`status-badge`, etc.) work seamlessly.
