# 🏛️ Architecture & Implementation Plan: External Mock Architecture, Proxy, & NgRx SignalStores

- **Timestamp:** 16_09_2026-20_58
- **Project:** BenchZero (ESN ERP)
- **Objective:**
  1. Remove 100% of hardcoded mock data from `src/` runtime application code.
  2. Implement an external mock REST API server (`mock-server/`) with realistic seeded JSON data.
  3. Wire Angular CLI reverse proxy (`proxy.conf.json`) to forward `/api/*` to the mock server.
  4. Implement domain HTTP API services using `HttpClient`.
  5. Implement state management using `@ngrx/signals` SignalStore (`signalStore`, `withState`, `withComputed`, `withMethods`, `patchState`).
  6. Ensure effortless backend substitution in the future by flipping the proxy target or `API_BASE_URL` token with zero changes to components or stores.

---

## 2. Directory & File Plan

### A. External Mock Infrastructure (Outside `src/`)
- `mock-server/data/consultants.json`: Seeded consultants with skills, statuses, TJM, days on bench.
- `mock-server/data/risk-overview.json`: Real-time financial exposure, active alerts, placement velocity.
- `mock-server/data/clients.json`: Key accounts, active staff counts, monthly billings.
- `mock-server/data/placements.json`: Pipeline stages (Matched, Pitch Sent, Interviewing, Signed).
- `mock-server/server.mjs`: Express server (port 3001) exposing REST routes (`GET /api/consultants`, `GET /api/risk/overview`, `GET /api/clients`, `GET /api/placements`, `POST /api/consultants`).
- `proxy.conf.json`: Angular CLI proxy mapping `/api` to `http://localhost:3001`.

### B. Core Communication & Token Setup (`src/app/core/`)
- `src/app/core/tokens/api.token.ts`: SSR-safe `API_BASE_URL` token (`''` in browser for proxy, `http://127.0.0.1:3001` in server platform).
- `src/app/app.config.ts`: Register `provideHttpClient(withFetch())`.

### C. NgRx State Management with Signals (`@ngrx/signals`)
- `src/app/features/consultants/stores/consultants.store.ts`:
  - `ConsultantsStore = signalStore(...)`
  - State: `consultants: Consultant[]`, `filterStatus: ConsultantStatus | 'ALL'`, `isLoading: boolean`, `error: string | null`
  - Computed: `filteredConsultants`, `benchCount`, `onMissionCount`, `endingSoonCount`
  - Methods: `loadAll()`, `setFilterStatus()`, `addConsultant()`
- `src/app/features/bench-risk/stores/bench-risk.store.ts`:
  - `BenchRiskStore = signalStore(...)`
  - State: `metrics: RiskOverview | null`, `highRiskConsultants: Consultant[]`, `isLoading: boolean`, `error: string | null`
  - Methods: `loadOverview()`
- `src/app/features/customers/stores/clients.store.ts`:
  - `ClientsStore = signalStore(...)`
  - State: `clients: ClientAccount[]`, `isLoading: boolean`, `error: string | null`
  - Methods: `loadClients()`
- `src/app/features/placements/stores/placements.store.ts`:
  - `PlacementsStore = signalStore(...)`
  - State: `opportunities: PlacementOpportunity[]`, `isLoading: boolean`, `error: string | null`
  - Methods: `loadOpportunities()`

### D. Component Refactoring (Zero Mock Data)
- `BenchRiskComponent`: Injects `BenchRiskStore`, dispatches `store.loadOverview()`, displays loading skeleton / reactive data from signals.
- `ConsultantsComponent`: Injects `ConsultantsStore`, dispatches `store.loadAll()`, uses `store.filteredConsultants()`.
- `CustomersComponent`: Injects `ClientsStore`, dispatches `store.loadClients()`.
- `PlacementsComponent`: Injects `PlacementsStore`, dispatches `store.loadOpportunities()`.

## 3. Future Removal / Production Backend Migration Plan

When the production backend is deployed to `79.137.14.75`:
1. **Zero Source Code Changes**: No components, stores, or services require modification.
2. In `proxy.conf.json`, update the target to the real backend host (`http://79.137.14.75:3000`), or in production Nginx, proxy `/api/` directly to the backend container.
3. Stop running the mock server.
